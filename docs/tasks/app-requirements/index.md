# 把应用想法整理成一页需求说明

明确使用者、操作步骤和验收条件，让一个小应用的范围可讨论。

下面使用虚构练习材料。示例结果为人工编写，供核对内容和格式。

::: platform doubao

## 1. 打开工具，准备材料

打开 [豆包网页版](https://www.doubao.com/chat/)，按页面提示完成登录。在对话输入框里发送下一步的完整文字。先用练习材料做一遍，再换成自己的资料。

## 2. 复制这段话并发送

<PromptBox>

请把以下虚构想法整理成一页应用需求说明。
想法：给家里的纸质书做一个借阅记录小网页。只有我一个人使用，先在自己的电脑使用；不做登录、支付、扫码和多人共享。
第一版需要：登记书名、借给谁、借出日期、约定归还日期；查看未归还列表；标记已归还。借阅记录需要能保存，关闭后再打开可继续查看。
请输出：使用者与目标、一次完整使用流程、字段表、第一版包含/不包含的功能、五条可操作的验收条件、尚需确认的问题。
不要直接写代码，不自行加入云端同步或提醒服务。保存方式由后续开发确认。

</PromptBox>

## 3. 对照结果，修正遗漏

下面是一种人工整理的参考结果，不是工具实测输出。AI 的措辞可以不同，事实、限制和关键内容应一致。

**一页说明的关键部分**

- 使用者：家庭藏书管理者本人。
- 流程：登记借阅 → 查看未归还记录 → 标记归还。
- 字段：书名、借阅人、借出日期、约定归还日期、归还状态。
- 范围：单人、本机使用；不含登录、支付和多人共享。
- 验收示例：新增一条记录后出现在未归还列表；标记归还后移出该列表；重开页面仍能查看已保存记录。
- 待确认：字段哪些必填，数据怎样导出备份。

如果回答超出了要求，可以继续发送：

<PromptBox>

把验收条件改成可以实际操作检查的句子，例如“新增后能看到记录”。删掉“体验流畅”“系统稳定”这类无法直接判定的描述。

</PromptBox>

## 4. 换成自己的材料

替换成自己的使用者和具体问题，先让需求相关人确认范围，再把这份说明交给设计或开发环节。

审阅后选中需要的结果复制到自己的文档，保留原始材料，方便以后复核。

:::
